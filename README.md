Сервис онлайн-записи клиентов на груминг через Telegram бота.
Клиенты записываются через бота, мастер управляет расписанием и подтверждает записи.

## Что умеет сервис

**Для клиентов (через Telegram бота):**

- Регистрация по имени и номеру телефона
- Добавление питомцев
- Запись на стрижку — выбор даты и времени
- Просмотр и отмена своих записей
- Автоматическое напоминание за 24 часа до визита

**Для мастера (через Telegram бота):**

- Просмотр записей на сегодня и завтра
- Подтверждение или отклонение заявок
- Создание шаблонов расписания через пошаговый диалог
- Управление расписанием — активация шаблонов, блокировка слотов
- Планирование отпуска и нерабочих периодов
- Договорные записи вне расписания
- Отметка завершённых визитов и no-show
- Блокировка проблемных клиентов

## Быстрый старт

### Шаг 1 — Создать Telegram бота

1. Откройте Telegram и найдите `@BotFather`
2. Отправьте `/newbot`, введите название и username (заканчивается на `bot`)
3. Сохраните полученный **токен** вида `7123456789:AAHdqTcvCHhvWUTvG...`

### Шаг 2 — Узнать свой Telegram ID

1. Найдите бота `@userinfobot` в Telegram
2. Отправьте любое сообщение — бот ответит вашим **ID** (числом вида `123456789`)

### Шаг 3 — Настроить проект

Создайте файл `.env` в корне проекта:

```bash
TELEGRAM_BOT_TOKEN=7123456789:AAHdqTcvCHhvWUTvG...
MASTER_TELEGRAM_ID=123456789
MASTER_ADDRESS=г. Москва, ул. Примерная, д. 1

DB_HOST=localhost
DB_PORT=5432
DB_NAME=groombook
DB_USER=postgres
DB_PASSWORD=postgres

# Необязательные настройки
GOOGLE_CREDENTIALS_PATH=src/main/resources/credentials.json
GOOGLE_CALENDAR_ID=primary
```

### Шаг 4 — Запустить базу данных

```bash
docker-compose up postgres -d
```

### Шаг 5 — Запустить приложение

```bash
./gradlew bootRun
```

При первом запуске Liquibase автоматически создаст все таблицы.
Когда появится `Started GroomBookApplication` — сервис работает.

### Шаг 6 — Проверить

Откройте бота в Telegram и отправьте `/start` — бот должен ответить.

## Настройка

В `src/main/resources/application.yaml` можно настроить параметры по умолчанию:

```yaml
grooming:
  timezone: Europe/Moscow    # ваш часовой пояс
  master:
    address: ""              # адрес студии — показывается клиентам
  google:
    calendar-id: primary      # ID календаря
    credentials-path: src/main/resources/credentials.json
```

## Управление через бота

### Команды для клиентов

Команда - Что делает
`/start` - Регистрация или приветствие
`/book` - Записаться на стрижку
`/mybookings` - Посмотреть свои записи или отменить их
`/addpet` - Добавить нового питомца
`/help` - Справка по командам клиента

### Команды для мастера

Команда - Что делает
`/start` - Приветствие и главное меню
`/today` - Все записи на сегодня
`/tomorrow` - Все записи на завтра
`/week` - Записи на ближайшую неделю
`/fortnight` - Записи на ближайшие 2 недели
`/newtemplate` - Создать новый шаблон расписания
`/schedule` - Управление расписанием (активация шаблонов, блокировка слотов)
`/vacation` - Заблокировать период (отпуск, болезнь)
`/manual` - Создать договорную запись вручную
`/blocked` - Список заблокированных клиентов
`/help` - Справка по командам мастера

## Первоначальная настройка расписания

После первого запуска расписание пустое — клиенты не смогут записаться пока вы не создадите и не активируете шаблон. Всё
делается через бота.

### Создать шаблон через бота

Отправьте `/newtemplate`. Бот проведёт через 5 шагов:

```
Шаг 1 — Название
  Введите: Стандартный

Шаг 2 — Рабочие дни
  [✅ Пн] [✅ Вт] [✅ Ср] [✅ Чт] [✅ Пт] [☐ Сб] [☐ Вс]
  Нажмите [➡️ Готово]

Шаг 3 — Начало рабочего дня
  [08:00] [09:00] [10:00] [11:00]

Шаг 4 — Конец рабочего дня
  [17:00] [18:00] [19:00] [20:00] [21:00]

Шаг 5 — Длительность слота
  [1 час] [2 часа] [3 часа]

Итог и подтверждение:
  📋 Стандартный
  Дни: Пн, Вт, Ср, Чт, Пт
  Время: 09:00 – 19:00 | Слот: 2 ч. | Слотов в день: 5
  [✅ Создать] [❌ Отмена]
```

### Активировать шаблон

1. Отправьте `/schedule` → **Шаблоны**
2. Выберите шаблон из списка
3. Введите дату начала: `дд.мм.гггг` (или `сегодня`)

Слоты на 14 дней вперёд сгенерируются автоматически.

### Создать несколько шаблонов

Создайте разные шаблоны для разных режимов работы и переключайтесь между ними:

Шаблон - Когда использовать

Стандартный (Пн–Пт, 09:00–19:00, 2ч) - Обычный режим
Высокий сезон (Пн–Сб, 09:00–20:00, 2ч) - Лето, праздники
Зима (Пн–Пт, 10:00–17:00, 2ч) - Сокращённый день

При переключении шаблона уже подтверждённые записи сохраняются.

### Управление расписанием

**Заблокировать слот** (врач, банк, личные дела):

1. `/schedule` → Заблокировать слот
2. Введите дату → выберите слот → введите причину (видна только вам)

**Отпуск или нерабочий период:**

1. `/vacation`
2. Введите период: `10.07.2025-20.07.2025`
3. Бот покажет записи попавшие в период — свяжитесь с клиентами вручную

**Договорная запись** (клиент договорился лично):

1. `/manual` → введите телефон клиента
2. Выберите питомца → введите дату и время

## Работа с Google Календарём

При подтверждении записи сервис создаёт событие в Google Календаре. При отмене — удаляет.

### Настройка (один раз)

**1. Создать сервисный аккаунт:**

1. https://console.cloud.google.com → ваш проект
2. **API и сервисы** → включить **Google Calendar API**
3. **Учётные данные** → **Создать** → **Сервисный аккаунт**
4. На странице аккаунта: **Ключи** → **Добавить ключ** → **JSON**
5. Переименуйте скачанный файл в `credentials.json` и положите в папку проекта

**2. Дать доступ к календарю:**

1. Google Календарь → три точки рядом с вашим календарём → **Настройки и доступ**
2. **Поделиться** → введите `client_email` из `credentials.json`
3. Роль: **Внесение изменений в мероприятия**

**3. Добавить в `.env`:**

```bash
# Путь к JSON-файлу (относительно корня или абсолютный)
GOOGLE_CREDENTIALS_PATH=src/main/resources/credentials.json

# ID календаря (по умолчанию 'primary')
GOOGLE_CALENDAR_ID=your_email@gmail.com
```

> Если Google Календарь не нужен — сервис работает и без него. При ошибке подключения бронь создаётся, просто без
> события в календаре.

## Особенности реализации и надежность

В проекте реализованы механизмы обеспечения целостности данных и отказоустойчивости:

- **Защита от двойного бронирования (Race Condition):** Используется пессимистическая блокировка записей в БД (`SELECT FOR UPDATE`) на уровне слотов времени и частичные уникальные индексы в PostgreSQL. Это гарантирует, что даже при одновременном нажатии кнопки записи несколькими пользователями, бронь получит только один из них, а остальные увидят корректное сообщение о занятости слота.
- **Отказоустойчивость внешних API:** Интеграция с Google Calendar защищена настроенными тайм-аутами. Если сервис Google недоступен или отвечает медленно, это не блокирует работу бота и не прерывает процесс создания брони в локальной базе данных.
- **Обработка ошибок:** Внедрен глобальный механизм перехвата исключений. В случае системного сбоя пользователь получит вежливое уведомление, а детали ошибки будут сохранены в логах с уникальным ID запроса для диагностики.
- **Миграции БД:** Структура базы данных управляется через Liquibase, что обеспечивает легкое развертывание и обновление схемы без потери данных.

## Структура проекта

```text
src/main/java/org/example/groombook/
  ├── exception       — исключения  
  ├── model/          — сущности базы данных
  ├── repository/     — запросы к базе данных
  ├── service/        — бизнес-логика
  ├── infrastructure/ — Telegram уведомления, Google Calendar
  └── bot/            — Telegram бот, обработчики команд
src/main/resources/
  ├── application.yaml — настройки приложения
  └── db/changelog/    — миграции Liquibase
```
